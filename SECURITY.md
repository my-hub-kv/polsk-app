# Security policy

Do not disclose vulnerabilities in a public issue. Use private repository vulnerability reporting or a security advisory if enabled, and do not include credentials or real participant data.

The supported version is the current main/released production line. Sensitive areas include authentication, invitations, profile switching, authorization, private channels, personal information, CSV export, deletion, and external adapters. Provider identity alone is not a vulnerability; exposed credentials or exploitable configuration are.

Maintainers assess and coordinate fixes. Never test against production data without explicit authorization.
