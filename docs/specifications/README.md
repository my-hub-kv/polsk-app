# Active specifications

An approved active specification is required for multiple-domain work, cross-app models, authentication/authorization changes, planner changes, complex/destructive migrations, external integrations, sensitive personal data, significant UI flow, or background processing.

```markdown
# Feature title
GitHub issue: #
Status: Draft | Approved | Implemented
## Problem
## Confirmed behaviour
## Out of scope
## Proposed implementation
## Alternatives considered
## Authorization rules
## Data model impact
## Service operations
## UI flow
## Failure and edge cases
## Security and privacy review
## Test plan
## Migration plan
## Documentation updates
## Rollout and rollback
```

Do not commit raw chain-of-thought or conversation transcripts. After implementation, move durable rules to product/domain docs, record technical decisions in ADRs, and archive the specification in `completed/` rather than leaving it stale.
