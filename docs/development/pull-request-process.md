# Pull-request process

Create/select a bounded issue, confirm acceptance criteria, and record a written feature brief in the issue when work spans several domains or carries material migration, authorization, or privacy risk. Work on a non-main or Codex task branch; run checks, update documentation, open a PR, let CI and available Codex review run, then require human review and approval before merge. Automatic deployment happens outside Codex’s authority.

PRs include summary, issue/specification link, behaviour, synthetic UI evidence, migration details, authorization/security impact, test evidence, documentation updates, deployment/rollout notes, and open risks.
